# CareerLens C4 architecture

The maintained model and diagrams live in the [CareerLens IcePanel landscape](https://app.icepanel.io/landscapes/zsv8gphn0T0n2Y93h1NS).

## Level 1: system context

The `CareerLens - System Context (C1)` diagram shows the product boundary and the systems that directly participate in its user-facing value.

| Element | C4 type | Responsibility |
| --- | --- | --- |
| Job Seeker | Person | Reviews vacancies, evaluates fit, saves decisions, and tracks applications. |
| CareerLens | Software system | Centralizes vacancies, personal evaluation, application tracking, and assistant-driven job-search workflows. |
| Vacancy Acquisition Service | External software system | Supplies normalized vacancy data. It is deliberately treated as a black box: sources, collection mechanisms, and internal processing are outside this model. |
| WorkOS | External software system | Authenticates invited users and returns verified identity information. |
| AI Assistant | External software system | Queries and evaluates vacancies through the CareerLens MCP boundary on behalf of the job seeker. |

The C1 view intentionally does not show deployable applications, databases, frameworks, job-board integrations, or implementation modules. Those belong to deeper C4 levels or to the black-box vacancy acquisition service.

## Level 1 flows

The context diagram carries three focused use-case flows instead of one overloaded end-to-end story:

### Sign-in and vacancy review

1. The job seeker opens CareerLens and requests their personalized workspace.
2. CareerLens checks for an active session and starts secure sign-in when required.
3. WorkOS authenticates the invited user.
4. CareerLens loads the personalized vacancy feed.

Outcome: the authenticated job seeker reaches a personalized vacancy workspace and can continue the job-search workflow.

### Vacancy synchronization

1. CareerLens starts a vacancy refresh.
2. The Vacancy Acquisition Service collects and normalizes vacancies as a black box.
3. CareerLens validates the normalized vacancy set.
4. CareerLens updates the vacancies available to users.

Outcome: fresh normalized vacancies are available without exposing sources, collection mechanisms, or acquisition internals.

### AI-assisted vacancy analysis

1. The AI Assistant interprets the job seeker's intent.
2. CareerLens serves user-scoped vacancy context through MCP.
3. The AI Assistant evaluates vacancy fit.
4. The job seeker reviews the assistant's assessment and remains responsible for the decision.

Outcome: an external assistant can support vacancy analysis through the CareerLens MCP boundary without taking control away from the job seeker.

## Maintenance contract

- IcePanel is the source of truth for model objects, relationships, and diagram layout.
- Repository documentation explains diagram intent and records the stable landscape link; it does not duplicate the diagram as a second editable model.
- Keep the vacancy acquisition boundary opaque at C1 unless its public system contract changes.
- Keep each Level 1 flow focused on one user goal or system responsibility. Add branches only when the alternative path changes an architectural interaction.
- Add Level 2 or Level 3 views only when they answer a concrete architecture question that C1 cannot.
