# Інтереси — план UI-перевірок

## Мета і межі

Перевірити керування інтересами та погоджену композицію картки: назва зі статусом,
ключові слова без видимого підпису, необов’язкове «Не включати», джерела нижче
розділювача, текстова пауза/відновлення та меню редагування/видалення.

Рівень — Storybook + Vitest Browser (Chromium). Це перевірка справжнього DOM,
розкладки, подій і доступності, а не E2E з Django. Новий тестовий рушій не потрібний.

Поза межами: авторизація WorkOS, ізоляція користувачів, серверна валідація,
збереження у PostgreSQL, реальний збір вакансій та публікація. UI-моки не доводять
ці властивості; їх перевіряють backend/API-тести та окремий інтеграційний smoke.

## Ризики та покриття

Пріоритет P1 — недоступна дія, втрата керованості станом або помилкова мутація.
P2 — зламана композиція, переповнення чи нечітке представлення даних.

| Ризик                                            | Спостережуваний результат                                                                                                                                 | Сторі                                                                                                                                       |
| ------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| P2: втрачена ієрархія картки                     | Назва → ключові слова → виключення → джерела за розділювачем; списки мають доступні назви, видимих підписів-двокрапок немає                               | `Interests/Card/Composition`                                                                                                                |
| P2: порожні необов’язкові поля створюють сміття  | Для активного інтересу немає «На паузі» та порожнього «Не включати»; порожній вибір джерел показує «Усі джерела»                                          | `ActiveAllSources`                                                                                                                          |
| P1: довга назва перекриває статус/дії            | Реальні межі назви, статусу, кнопок не перетинаються; повна назва доступна через `title`                                                                  | `LongContent*`                                                                                                                              |
| P2: багато токенів виходять за картку            | Усі 30 ключових слів присутні; токен із 50 символів переноситься; елементи всередині меж картки                                                           | `LongContent*`                                                                                                                              |
| P1: злам на межі desktop/mobile                  | 767 px — дії під назвою, 768 px — праворуч; touch targets на mobile ≥44 px; джерела досяжні прокручуванням                                                | `LongContentMobile`, `LongContentMobileBoundary`, `LongContentDesktopBoundary`                                                              |
| P1: меню не працює з клавіатурою                 | Tab/Enter відкривають редагування з посиланням на trigger; Escape не викликає видалення і повертає фокус; Shift+Tab/Enter запускають відновлення один раз | `KeyboardActions`                                                                                                                           |
| P1: остання картка під нижньою навігацією        | Прокручується сторінка, не оболонка; меню десятого інтересу над навігацією, видиме та не перекрите іншим елементом                                        | `Layout/AuthenticatedLayout/InterestsPageMobile`                                                                                            |
| P1: немає відновлення після завантаження/помилки | Loading, empty, retry, ліміт і доступність створення                                                                                                      | `Interests/Page/Loading`, `LoadFailed`, `Empty`, `List`, `LimitReached`                                                                     |
| P1: неправильне створення або редагування        | Форма надсилає потрібний payload і CSRF; помилки прив’язані до полів; після успіху список та фокус оновлені                                               | `Create*`, `Edit`, `EditNoChanges`                                                                                                          |
| P1: повторна зміна активності або втрата фокуса  | Пауза ↔ відновлення, pending блокує суміжні дії, помилка видима, retry працює                                                                             | `PauseResume`, `PausePending`, `PauseFailed`                                                                                                |
| P1: старий reload перезаписує новіші зміни       | Після паузи двох різних карток запізніла відповідь першого GET не відновлює активність і не приховує список помилкою                                      | `Interests/Reloads/OlderSuccessAfterNewerSuccess`, `OlderFailureAfterNewerSuccess`                                                          |
| P1: помилкове видалення                          | Підтвердження, failure, останній елемент, ліміт, відкладена помилка після скасування                                                                      | `Delete*`                                                                                                                                   |
| P1: кнопки форми недосяжні після resize          | Поля і діалог обмежені вікном, scroll owner визначений, дії доступні з клавіатури                                                                         | `EditResizedFields`, `EditShortViewport`, `EditHeightBoundary`, `EditAboveHeightBoundary`, `CreateValidationNarrow`, `DeleteLongNameNarrow` |
| P2: регресія теми/доступності                    | Axe-порушення провалюють сторі (`a11y.test: error`); є світла й темна композиції                                                                          | `Composition`, `LongContentDark`, `Page/Dark`, `DeleteDark`                                                                                 |

`LongContent*` використовує граничні дані з доменного контракту: назва 100 символів,
30 ключових слів, окремий токен 50 символів. Viewport береться з реєстру Storybook;
тест перевіряє фактичну ширину: 390, 767, 768 або 1440 CSS px.
Не дублюємо всі комбінації тем і розмірів: тема не змінює алгоритм розкладки.

## Редагування і збереження

`Interests/Editing` перевіряє повну сторінку, підміняючи лише HTTP-межу.
Відкладені запити керуються явними promises, без таймерів; teardown завершує їх
і відновлює `fetch` та cookie.

| Стан / перехід                              | Очікування                                                                                                                                                                           | Сторі                            |
| ------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------- |
| Зміни → скасування → повторне відкриття     | PATCH відсутній, чернетка скинута, вихідні назва/джерела відновлені, фокус на меню                                                                                                   | `CancelAndReopen`                |
| Зміни → PATCH pending → GET pending → успіх | Поля/checkbox/кнопки заблоковані, `aria-busy=true`, Enter не дублює PATCH, Escape і натискання зовні не закривають діалог; закриття лише після reload, фокус на оновленому меню      | `PendingSaveAndReload`           |
| PATCH 500 → повторна спроба                 | Назва, ключові/стоп-слова і джерела не губляться; поля та кнопка знову доступні; повторний PATCH має той самий payload, картка та повторно відкрита форма містять збережені значення | `FailurePreservesDraftAndRetry`  |
| PATCH 422 → виправлення                     | Значення збережено, помилка має `aria-invalid` і доступний опис; після виправлення успішно збережено                                                                                 | `ValidationFailureAndCorrection` |
| PATCH успішний → GET 500 → retry            | Помилка завантаження списку, не помилка запису; повторюється GET, не PATCH, нове значення показується після відновлення                                                              | `SavedButReloadFailed`           |

Чернетка зберігається при помилці у відкритій формі, але свідоме скасування до
запису її відкидає. Pending блокує закриття до завершення PATCH і reload, щоб
пізня відповідь не закрила інший редактор. Перезавантаження вкладки, вихід із
маршруту та втрата мережі після фактичного server commit не гарантують збереження
чернетки або exactly-once: для цього потрібен окремий узгоджений контракт.

## Дані та ізоляція

- `interest-card.stories.tsx` рендерить справжню картку; spies стоять лише на її
  публічних callbacks. Вони не доводять відкриття діалогу або HTTP-запит.
- `interests-page.stories.tsx` перевіряє зв’язок картки з формами і мутаціями,
  підміняючи лише HTTP-межу; кожна сторі створює власний стан і відновлює `fetch`.
- Існуючий API-mock контракт звіряється з `openapi.json` при змінах API.
- Особисті дані, справжні облікові записи й production-запити не використовуються.

## Запуск із `frontend/`

Потрібні встановлені залежності та Chromium Playwright. Окремі Vite, Storybook,
Django або база даних для цих тестів не потрібні.

```sh
npx vitest --project=storybook --run src/features/interests/components/interest-card.stories.tsx src/features/interests/components/interests-page.stories.tsx src/features/interests/components/interest-editing.stories.tsx
npx vitest --project=storybook --run src/components/authenticated-layout.stories.tsx -t 'Interests Page'
npx tsc -b --pretty false
```

Перед ширшою передачею змін — `just frontend-test` з кореня проєкту та
`npm run build --prefix frontend`, відповідно до `CONTRIBUTING.md`.

## Критерії приймання

- Названі focused suites проходять без прихованих повторних запусків і вимкнення a11y.
- Перевірки геометрії виконуються у справжньому браузері, не за класами Tailwind.
- Візуально переглянуті звичайна/довга картка, mobile і desktop, світла/темна теми.
- Погодження власником залишається окремим: геометрія й axe не оцінюють естетику.

## Залишкові ризики

Немає автоматичного pixel-diff для `.pen` і браузера; макети перевіряються вручну.
Chromium не доводить сумісність Safari/Firefox або роботу реального screen reader.
Axe не замінює ручного огляду всіх контрастів і фокусних станів.
Зміни API, навігації або рушія браузера — привід повторно оцінити ці межі, а не
автоматично розширювати матрицю тестів.
